# dotenv 短片重写：一张标签，让程序读到名字

候选 v2，2026-11-07。交付为完整文字与视觉方案，未生成声音、动画或视频，未执行 dotenv。目标为约 45 秒连续解释片；时间均为作者预算，必须用完整本地录音的实测时长修订后才能生产。独立事实 Judge 与最终用户视听验收待定。v1 原文逐字节保留于 `docs/dotenv-story-redesign-v1.md`（SHA-256 `cce4c94771577461f3045bfd5bd274604334312acab5cc4abc63de2dd84d4627`）；原独立事实报告保留不改。

## 观众得到什么

先看到一个具体结果：程序说出 `Hello Dotenv`。再沿着同一张写有名字的纸标签，理解这个名字怎样从 `.env` 进入程序可读取的位置。只讲 README 的一个完整使用例子，不再以 String、Buffer、Object 三个术语开场。核心价值是**把要使用的配置值放在代码之外，再让代码读取它**，不是声称 dotenv 能生成界面、自动修复程序或完成部署。

这里扩展了旧预览仅讲 `parse` 的范围：新故事使用 README 的 `config()` 用法，不可把旧 parse 场景的事实绑定直接复用。纸标签与收纳槽是教学隐喻；问候语是 README 的输出示例，均不冒充本次实测。

本故事限定为默认不覆盖已有环境变量的用法：进程环境中 `HELLO` 原先未设置，`.env` 文件可读取且配置成功。空槽标注为“未设置”，不显示 `HELLO=""`，因为已有空字符串也是已设置的值。文件成功读取属于这个教学示例的前提，不是本次运行回执；若已有同名值，默认会保留它，不应套用本故事的结果（E5、E6）。

## 完整中文旁白

> 程序里这一声“你好”，名字是从哪儿来的？
>
> 看这张标签。名字先写在一个点 env 文件里，和代码分开放。
>
> 这个例子里，环境变量 HELLO 还没设置。启动时，dotenv 成功读入文件，把这个名字填进去。
>
> 接着，示例程序按名字去读这个值，再拼进问候语。
>
> 于是，文件里的 Dotenv，就出现在这句 Hello Dotenv 里。
>
> dotenv 负责把配置交给程序；问候语，是程序自己拼的。这里演示的是文档示例，没有运行项目。

旁白里的“按名字”指读取名为 `HELLO` 的变量；画面明确显示 `HELLO` 键和 `Dotenv` 值，不能把两者画成同一概念。英文词的实际读法与时长待本地录音试听确认，不以字符数量推定对齐。
