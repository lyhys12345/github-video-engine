# Source-backed documented-summary card alternative

This slice adds `explanation narrative-card --task <existing narrative> --spec <card.json> --data <state> --out <new-dir>` and `narrative-card-excerpt --task <card task> --spec <selection.json> --data <state> --out <new-dir>`, with corresponding `-status` and `-export` actions.

A finite2–3-node linear or three-node choice diagram may replace only an unresolved closing adapter in a new complete generated `repository-narrative-plan/1.1` fork. This explicitly narrows the closing to a documented-summary alternative. It does not produce the original monitoring/observed-output capability, resolve a measurement gap, or alter the old1.0 plan. Renderability is `supported-card`; fact disposition remains pending. Original scene text/disposition and still-missing capability remain in resolution-ledger.json and visible disclosure.

Every node and edge references existing source-documented claims. Exact parent plan, source binding, original scene hash, labels, geometry, highlight schedule, font and current movie are bound in a new review packet. Pinned source bytes and exact quotations are rechecked through the existing narrative loader. This proves structural/source integrity, not semantic correctness of an authored summary or arrow relationship. Unsupported primitives, arbitrary URLs/code/paths, unknown claims, stale mappings, gap promotion and incomplete/invalid schedules are rejected. No source or target code is executed.

The new excerpt consumes a verified typed card movie and exactly bound historical Story slices. It uses reset boundaries, keeps every unresolved evidence gap visible, and records supported scene omissions. It cannot assert cross-card/Story state continuation. The actual two-project examples reuse existing source clips historically and render only the new4-second card and15-second technical excerpts under the current engine; original source environments/hashes are retained, not relabelled. Audio is explicitly omitted and new narration is export-only. These are not formal full films.

Edit card.json and rerun narrative-card to create a new card task, generated plan fork and pending review packet; then update expectedCardPlanHash/cardTaskId for the excerpt. narrative.json is the complete generated fork view, not an input accepted by the legacy1.0 narrative-plan command. All prior inputs/tasks/receipts remain historical. Moved input files and relocated state are verified without reading the original source path.

The current operator scope is necessary targeted tests and actual short-media checks only. No full regression, independent Judge, push, deployment or acceptance is part of this checkpoint. User decision and current facts/media/final review remain pending.
