# Complete-story narration revision checkpoint

`explanation run-revise --author <existing author> --spec <explicit patch.json> --out <new candidate>` preserves the original data and creates a new `author/` plus `revision.json`. The patch names the exact old author hash and per-shot narration hash, supplies the actual new text, and explicitly chooses `recompute-existing-whole-shot-estimates` / `rebuild-single-whole-recording-cue`.

The helper supports complete run-author2.0, exact produced shot ownership and existing whole-shot selections. It synchronizes Story shot text, linked narrative scene text, single full-recording caption character range and mechanically derived selection ranges. It preserves source bindings, evidence, visualSeconds/hold/transition settings, animation, gap dispositions and all old inputs. Scene task links are reset to their standard bind tokens; the executor resolves actual IDs. No measured-duration padding, stretching, truncation, model authoring or semantic approval is performed. Existing multi-cue/aligned captions are rejected rather than automatically repartitioned; unsupported/ambiguous data needs an explicit author revision. Optional old audio-binding files are omitted from the new author and listed by hash, never deleted from the original.

`explanation run ... --author <new author> --through speech` now reuses the existing30fps caption timing and physical text-layout validators before animation. The report separately checks measured whole-recording fit and the exact caller-authored caption characters/samples/readability. Invalid captions return `awaiting-session-agent-captions`; long recordings return the existing timing checkpoint. `readyForAnimation` is true only when both pass. Caption timing remains caller-authored and speech alignment/listening remain unverified. No automatic resegmentation occurs. Legacy render-first voice checkpoints remain unchanged.
