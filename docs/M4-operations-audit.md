# M4 独立工程预备：只读执行审计

本模块用于推进原路线中的恢复、版本、缓存和费用可解释性。它不是 M4 完成声明，不创建 G4/G5/G6，不把 M2 的预演批准变成完整制作权限。

```sh
pnpm gve audit --data demo-output/persisted-job
pnpm gve audit --data work/m1-live-state --out work/new-audit-report.json
pnpm run test:operations
```

`--data` 必须明确给出一个已存在的目录。常规 CLI 状态布局是 `DATA/jobs.sqlite` 与 `DATA/workflow/{workflow,tasks,production}.sqlite`；也可明确传入直接的 workflow 状态目录。命令不递归搜索其他测试/审阅状态，避免把恢复实验的复制数据误算成额外生产执行。

没有浏览器、FFmpeg 或网络仍可审计。此命令不创建缺失的源状态目录/数据库，不实例化会迁移或建表的运行时 Store，不 resume/cancel/repair/approve，也不下载媒体。它会创建并清理自己拥有的临时数据库副本，见下方一致性说明。可选 `--out` 只新建用户指定报告；已有文件保留并非零退出。正常诊断报告中的 `ok` 代表所覆盖数据的审计检查结果，**不代表历史失败任务已成功、审批已通过或产品里程碑已验收**。

## 检查范围

- 读取数据库版本/固定表结构、健康检查和原始 SQL 键；核对 JSON 记录、完整输入指纹、任务/步骤/修订/制作包及审批关联。
- 按内容地址、声明大小和实际 SHA-256 核查已引用文件；受限地检查 JSON 内嵌产物引用；损坏、缺失或越界路径明确失败。M0 的验证 spec、素材映射、评价目标与发布清单还须与记录中的任务/阶段输出一致；只有 blob 自身哈希正确不足以证明它属于该任务。
- 列出当前选择与保留历史、活动/过期租约、失败和取消、实际尝试数与缓存/检查点复用事件。预演批准范围从任务类型＋制作包哈希推导；持久化 scope 标签不一致时明确失败，不能据此拆分额度。预算跨环境累加，已失败的尝试也计入；缓存读取不追加尝试。
- 审批是已记录的历史对象，审计不会重新给予任何 gate，也不会宣称重新听过视频或验证了 judge 的主观判断。

对历史制作包要区分“不兼容当前读取器”与“字节损坏”。实际状态中有两个保留的旧 `schemaVersion:1.0` 制作包缺少后来要求的 `motionAudioScriptId`；原字节与哈希仍有效。诊断保留这个版本兼容性缺口，不给旧对象偷偷补字段或修改历史批准。

## 一致性与费用边界

实测发现，即便使用 SQLite 的 `readOnly:true`，直接打开关闭后的 WAL 数据库仍会在源目录创建 `-wal`/`-shm` 文件。因此修复后先在上限内读取源 main 和现存 WAL，检查文件集合、字节及身份稳定性，放到独立临时目录，再只读打开副本执行事务。不会使用忽略 WAL 的 immutable URI 假装获得完整数据，也不会复制一个活动 main 文件后丢弃尚未 checkpoint 的提交。

每个副本数据库使用自己的只读事务；多个数据库和文件系统之间没有一个联合原子快照。运行中的生产者可能造成跨库观察不一致，报告必须明确这项局限。需要完整审计时应在本轮执行结束后再运行；本命令不会替用户停止任何 worker。若源在复制时变化，报告未完成/失败而非自动修复。

原有历史运行时没有金额账本。制作包中的 `maxPaidUsd:0` 是许可/预算上限，不能充当已发生金额的收据。历史实际付费金额显示为 `unknown / not-recorded`、数值 `null`，并给出覆盖说明。后续 usage slice 为新任务加入版本化执行/本地费用记录；当前审计报告版本为 `operations-audit/1.1`，同时支持无账本的旧 tasks DB 0 与有账本的 DB 1。旧金额不回填；完整项目成本和所有版本修改功能仍未完成，详见 `M4-usage-design.md`。已验收的旧审计 1.0 候选及原始文档保存在 preflight-4/frozen，不改写旧结论。

已有 M2 评价格式没有目标视频哈希，无法独立复原其确切评价对象；报告明确这项旧格式来源限制，不通过“通过标志”声称完成新媒体检查。M0 评价具有该目标字段，审计会验证。完整 M4 的新制作评价收据仍需后续实现。

源数据/文件由本地状态读取，不执行其中嵌入的指令、URL 或代码。表/行/文档/产物遍历有上限；超过上限是未完成检查，不能截断后输出绿色通过。

## 保存与验收

新增审计模块前，现有 M2 候选列出的 136 个文件已逐一验证哈希并保存在 `reviews/M2/round-1/frozen-before-M4-audit/`。旧报告仍对应旧源码/媒体；此后新增代码的结果按新候选重新验证，不复用旧版本结论。

本功能合同见 `reviews/M4/preflight-contract.md`，范围为 OA-01–08。实际命令、测试数量、原始失败及独立 product/reliability/evidence/security 预备审查，待本轮执行完成后写入结果记录。M2 视听缺口和完整 M3/M4 验收始终单独保留。
