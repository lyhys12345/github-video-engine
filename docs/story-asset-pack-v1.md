# Bounded authored story asset pack v1

`story asset-plan --spec <story.json> --root <source-root> --plan <animation.json> --voice <bindings.json> --data <state>` persists one SQLite/CAS task of kind `experimental-story-asset-pack-v1`. Identical captured input and compiler/tool versions reuse its verified result. `story asset-status --task <id> --data <state>` verifies the entire closure, and `story asset-export --task <id> --data <state> --out <new-directory>` publishes a complete `bundle` after staging. Existing output directories and state/output overlap are rejected. Use a new path for a second export.

The package includes original and portable story, exact source bytes, animation, complete estimated frame timeline, research handoff, statements and inference rationale with exact source lines/URLs/hashes, three diagnostic SVG samples per shot, manifest, and voice handoff. SVG metadata carries full applicable evidence; visible labels identify illustration, inference and author-chosen numeric parameters. `index.html` opens the sampled frames and evidence files locally. This is a bounded integration of authored assets, not a rendered movie, automatic project understanding, animation selection or production approval. Historical story and animation commands remain separate and unchanged.

Voice bindings use the existing `VoiceBindingSchema`. Paths resolve from the CLI working directory. Every clip requires exact current narration in its caller declaration, matching story/shot identity, unique shot ID and exact hash. Audio is captured once (50 MB per clip, 100 MB total), then only the captured bytes are measured in an owned temporary directory. One audio stream, no video and finite positive duration are required. Export contains those exact audio bytes at `audio/<shot>.bin`; the format is retained internally and FFprobe/player format sniffing can read them. No new narration is generated. Current REA/rembg recordings are absent; empty bindings leave all shots explicitly pending and estimate-only. The included opacity fixture uses an actual one-second synthetic PCM tone labeled **not speech**. Its transcript is only a caller declaration and does not assert that the tone speaks any words.

Measurement receipts, exact audio digests and FFprobe version are bound to the task input. Status/export verify that binding and rederive reports without rerunning FFprobe or dereferencing original paths. They do not independently authenticate spoken words or prove the original probe's correctness. Reported fit compares measured audio duration with the estimated story interval; oversized clips remain `fits: false`, and the animation timeline is never automatically retimed, stretched or truncated. Listening, voice identity/quality and final continuous audiovisual acceptance remain pending.

The task fingerprint includes source/animation/story/narration/timing bytes, portable voice declarations and captured audio digests, bound probe receipts, compiler source hashes and package/lock/config hashes. Source edits require an updated declared source hash. Narration edits require fresh exact declarations. All changes create new task identities and preserve old outputs. Status/export validate exact paths, file coverage, CAS bytes/fingerprints and deterministic research/timeline/SVG/report/manifest derivations. Valid-hash substitutions of derived outputs still fail against bound inputs. Invalid actual media creates a durable failed task. Cancellation after a partial CAS commit creates no successful result; the same planning input can resume within three attempts.

Run `pnpm test:asset-pack` and `pnpm typecheck`. `scripts/prepare-asset-closure-fixtures.ts` creates the explicitly synthetic opacity fixture and pending voice declarations; `scripts/exercise-asset-closure.ts` runs real public CLI cases, cache/export, four edit axes, stale narration rejection, actual bad-media failure and child-process cancellation/retry. `scripts/rasterize-asset-closure.ps1` produces review-only PNGs with exact exported SVG hashes and rasterizer version. PNGs are separate review evidence, not part of the runtime task. Existing sandbox policy may reject the CAS hard-link primitive with EPERM; the same unchanged legacy tests also fail there. Local verification requires filesystem permission for those atomic commits.

No paid API, target repository execution, deployment, full movie generation or listening approval is part of this closure.
