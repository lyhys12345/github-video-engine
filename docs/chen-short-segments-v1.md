# Bounded current-story Chen segments

`node --import tsx scripts/render-short-segment.ts <segment-input.json> <new-output-directory>` renders one selected short passage from a verified exported story asset pack. It accepts one exact continuous recording, verifies its bytes and current selected narration declaration, measures the captured recording with FFprobe, and preserves the complete source audio. It performs no generation, paid call, target-project execution or publication. The accompanying generation receipt records the separately authorized ElevenLabs Free UI operation.

The presentation is a separate reusable SVG layout for authored rule-building or foreground-mask application. It does not change the historical diagnostic preview renderer. The visual plan binds selected original shot IDs, claims, exact caption text, parameters and visible disclosures. REA demonstrates source condition `<13` and source increment `0.001`, with a separately labeled authored demonstration range of 6–12. rembg uses the same synthetic subject and mask, removing the background while retaining the subject. Neither visual records actual target execution.

The current passages are REA shot-5 and rembg shots 3→4. Their new source recordings measure 13.792625 and 11.311 seconds. Current rendered outputs are `examples/chen-segments-v1/rea-v4` (14.8 seconds, 444 frames) and `examples/chen-segments-v1/rembg-v4` (370 frames, approximately 12.333 seconds). Each is portrait 1080×1920 at 30 fps, H264 limited-range yuv420p / BT709 with AAC stereo at 48 kHz. The renderer adds 0.4 seconds before the unchanged source playback and at least 0.6 seconds afterwards; frame quantization can add less than 1/30 second. Audio conversion resamples/encodes and pads silence; it never time-stretches narration or cuts source speech to fit an estimate.

Caption clauses are allocated by text weight within the actual measured continuous recording. JSON includes both original source-time windows and output frame/time windows. This is explicitly estimated allocation, not provider timestamps, forced alignment, manual listening or proof of spoken-word timing. Listening, exact synchronization, voice naturalness, continuous audiovisual rhythm and final owner acceptance remain pending. SRT and burned-in captions share the same cue table.

For a new render, `cueTimingPath` may point to a strict `schemaVersion: "1.1"` sidecar with a caller-declared `manual-listening` or `forced-alignment-reviewed` method. It must bind the exact audio and transcript SHA-256 values, match the measured duration, and include `captionTextSha256` in phase order: one SHA-256 per raw `phase.captionText` UTF-8 string, with no Unicode, whitespace or punctuation normalization. Boundaries must cover every caption phase monotonically and leave at least four rendered frames per cue. Missing/reordered/mismatched hashes and changed phase segmentation reject even when the full transcript and phase count stay the same. Both direct timeline construction and rendering validate the sidecar. It is copied into the output and included in the immutable fingerprint; changing only its bytes invalidates timeline, captions, frames, MP4 and review approval.

Timeline methods are labeled `caller-declared-manual-listening-boundaries` and `caller-declared-forced-alignment-reviewed-boundaries`, with cue confidence `caller-declared-reviewed-timing-independent-unverified`. `timingEvidence` retains `reviewBasis` and records `source: "caller-declared"`, `independentTimingReview: "UNVERIFIED"` and `ownerAcceptance: "pending"`. Evaluation reports `caller-declared-boundaries-independent-unverified-owner-pending`. A sidecar supplies a caller declaration; transcript accuracy, voice quality, independent timing review and final owner acceptance remain unproved. Without one, the renderer retains the existing text-weighted estimated method and confidence.

Schema 1.0 is rejected with a requirement to review current segmentation again. Migration cannot merely add hashes or change the version and treat those edits as a completed review: review the exact current caption boundaries, then create a 1.1 sidecar with that basis. There is no automatic promotion or fallback for invalid timing input, and no historical report or media is rewritten.

Each successful directory preserves input, visual plan, original captured audio, generation receipt, complete source asset closure, selected-narration binding, cue JSON/SRT, locked implementation snapshot, actual FFmpeg/FFprobe commands and raw reports, final MP4 and independent PCM narration track. Samples cover every caption and both sides of transitions. A startup watchdog kills only its own renderer process tree if local browser launch exceeds 45 seconds. Existing destinations are rejected, and implementation edits during a render reject the result. Use a new versioned directory after fixing a failure.
