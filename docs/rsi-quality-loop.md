# Evidence-driven Skill improvement

RSI here means bounded, session-agent-led improvement of the reusable Skill and engine. It is not an autonomous model dispatcher, self-awarded quality certification, or permission to generate unapproved videos.

## Modules and checkpoints

1. Persist creative requirements: duration, style, voice, audience, platform and language; distinguish explicit choices from delegated choices and unresolved requirements. Bind changes to reviewable inputs.
2. Freeze an evaluation set and compare candidate vs baseline without disclosing which is newer to reviewers. Use VoiceStudio for audible result/utility, The World We Know for real product interaction, REA for causal explanation, and one held-out repository for generalization.
3. Convert review findings into structured, bounded repairs at the responsible layer: evidence, content selection, media acquisition, shot plan, narration, renderer or assembly. Preserve failed candidates and raw dissent.
4. Validate natural-language edits and fresh-session use across projects. Save each completed module separately with commands run, observed results, unresolved limitations and a Git checkpoint.

Module 1 is engineering groundwork. Modules 2–4 require additional execution and are not completed merely because this document exists. No whole video is generated until the owner approves its particular script/storyboard.

## Experiment contract

Before changing a candidate, record baseline code revision, exact input requirements, source revisions, candidate/script/media hashes, raw feedback, one improvement hypothesis, affected layer, and acceptance criteria. Keep evaluation fixtures and rubric fixed for the comparison. A bug fix may change the rubric only as a separate documented revision, requiring both baseline and candidate to be reassessed.

Use at most three repair attempts per experiment by default. Stop earlier on missing evidence, required modality, permissions or a regression that cannot be fixed within scope. Report the blocker; do not switch reviewers or loosen criteria to manufacture a pass. Paid services, target repository execution and publication still require their own authorization.

Reviewers receive identical audience/requirements, source evidence and anonymously labelled candidates. Separate viewer comprehension, factual support, and production quality. Report ties and regressions as well as improvements. A second repository must exercise the changed generic capability before claiming cross-project improvement; holdout failures remain visible.

## What counts as evidence

- Contract/runtime tests prove the particular invariants tested, not creative quality.
- Actual frame inspection can support readability and visual findings at those timestamps, not uninterrupted viewing or listening.
- Voice naturalness needs actual listening; inaccessible audio remains UNVERIFIED.
- Hook/comprehension reviewer scores are proxies, not measured platform retention or star conversion.
- User approval applies only to the exact candidate; changing material content invalidates it.
- A committed file or a Git checkpoint is not proof of a successful remote push.

Do not redistribute private voice references or model weights.

Handoff notes stay outside the code repository, per owner preference. This document is the reusable engineering protocol, not a session handoff.
