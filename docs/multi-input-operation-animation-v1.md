# Source-bound two-input operation animation v1

Evidence schema 1.3 and animation 1.3 introduce a bounded two-input capability. Each new evidence graph contains exactly 3 distinct objects (two retained inputs and a separate output), one tool and one `combine-inputs` source-process summary. It is not an atomic API-call or execution claim. Modes are deliberately concrete: `masked-image` (image + mask → cutout, transparent RGBA base explicitly recorded as a source constant) and `ordered-pages` (two donor pages → new PDF, exact distinct source-page order explicitly recorded). Every input link, output and constant/order has a nonempty source-claim binding whose union equals the operation claims. Missing/duplicate/unknown objects, output-as-input, unknown/duplicate claims, unsupported kinds/tools, invented geometry and missing/repeated PDF order are refused. Semantically irrelevant but structurally valid quotes still require real review; reference validity cannot certify entailment.

The animation author chooses only the existing operation ID and positive ordered phase times. Source objects, identities, tool and claims are derived; both inputs stay visible while independent illustrative signals converge, the tool activates and an independent output builds. Existing source-object visuals are reused for image/mask/cutout; PDF pages have donor/page labels and matching colors, with output order drawn explicitly. These are synthetic object depictions, not real photo/model pixels or actual PDF contents. The full native stage preserves the source frame and reserves the caption area. All actual display strings, connections, source hashes, choreography, full recordings/captions and movie digest enter the pending execution facts packet.

Old evidence/animation profiles remain unchanged. The new `multi-input/1.0` narrative adapter and `multi-input-operation/1.0` per-scene animation profile are explicit; old shorthand `extract`/`composite` operations are not silently converted. New evidence cannot use legacy animation to bypass its connection requirements. The current scene normalizer also accepts the new profile for the unified complete run. The usual owned JSON data rules, source binding and no-target-execution restrictions remain in force; the session Agent authors content rather than asking the user to edit JSON or dispatching a hidden model.
