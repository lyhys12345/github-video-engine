# Exact-quote workspace narration editing

`explanation edit-narration --workspace OWNED --spec REQUEST.json --out OWNED/edits/NEW [--through speech|preview]` connects a session-authored prose replacement to the verified current author and existing run-revise/run pipeline. Default is speech. Explicit preview produces an experimental editable technical preview, never formal-film approval.

The user still gives prose preferences. The current Session Agent reads workspace-status/current narration, chooses the exact intended old paragraph and writes the new paragraph. The deterministic executor does not interpret free-form language or call a model. Request schema is workspace-narration-quote-edit/1.0 with expectedCurrentResultSha256 copied from workspace-status, oldText and newText. Exact old text must uniquely match one complete produced single-shot scene. Approximate/duplicate matches, gaps and multi-shot partitions are refused, not guessed. The engine derives current author hash, shot ID and old-script hash and delegates to the existing bounded revision helper. Existing multi-cue captions are not automatically resegmented.

Candidates remain inside the owning workspace. Exact request bytes, verified source/current context and the immutable revision report are retained. A stale checkpoint is refused before a new candidate is created. After preparation, run checks checkpoint and owning-author hashes again while holding its existing workspace lock; an intervening workspace/author change cannot dispatch speech or overwrite another candidate. Existing run callers are unchanged because this precondition is optional.

Once a complete context/candidate was saved, retrying identical request/out resumes native cached stages if the original context is still current, or returns the verified current candidate with zero dispatch if already completed. A speech checkpoint can be advanced with explicit through preview using the same request/out. Different request bytes, altered candidate files or a workspace advanced to another author are refused; history is never overwritten. Interrupted filesystem creation before edit-context.json exists is retained for inspection and requires a fresh output, not silent replacement. These are engineering guards, not authenticated author identity or semantic approval.

Actual verification used an independent readonly-backed-up copy at C:/Users/luyuh/Documents/Codex/gve-qe. The exact request changed the first narration from `美元符和问号需要转义。` to `用户文本里的特殊字符，需要先转义。`. One CLI call completed measured speech and a75-second/2250-frame/7-scene editable preview. An exact retry returned existing-edit-checkpoint with actionsExecuted=0 and the same task. A stale request/new output created neither a candidate nor a task. Original author hash and old preview stayed valid.

The software version changed, so source previews were refreshed rather than falsely reported as cross-version hits. Unchanged speech remained cached; voice composition reused the measurement-stage receipts. Both old and new75-second outputs passed exact whole-recording PCM comparison (14 recordings), exact caption text,56rendered cue-boundary checks, actual H264/AAC count/duration and retained-task/media hash validation. Builder sampled the changed first caption in its reserved area. Old preview retains its original engine environment; only the new movie is asserted against this source version.
