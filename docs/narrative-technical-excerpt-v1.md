# Narrative technical excerpt v1

This profile makes a continuously playable **silent technical excerpt**, not a complete finished film or a state-continuous story. It connects an existing complete narrative to verified Story previews through exact ordered shot slices. Presentation sequence was inspected first: it accepts a different preview task type and inserts Separate example cards, so its task IDs/semantics are not reused or weakened here. This layer reuses existing Story asset/preview rendering, TaskRunner/CAS, safe publication, owned runtime cleanup, FFmpeg command handling and strict movie verification.

First use the existing `story asset-plan --task <bound-story-task> --plan <authored-animation.json> --voice <explicit-silent-voice.json> --data <state>` and `story preview-render --task <asset-task> --mode silent --presentation audience-v1 --data <state>`. Animation is human/agent authored. No arbitrary GitHub code or model is executed.

Then run `explanation narrative-preview --task <narrative-task> --spec <excerpt.json> --data <state> --out <new-directory>`. The spec schemaVersion is narrative-technical-excerpt/1.0, expectedNarrativePlanHash names the exact parent, mode is silent, fps is30, and scenes contains ordered entries. A supported entry has kind story-slice, sceneId, boundary reset, previewTaskId, expectedPreviewManifestSha256, and slices of `{shotId,startFrame,endFrame}` relative to each source shot. Those shot IDs must exactly equal the scene's parent mapping, with no missing, repeated or extra shot. Each slice is at most180 frames. A gap entry has kind placeholder, sceneId, boundary reset and frames60–120. State continuation, narration or another clock is refused by this profile.

At least two supported scenes are required. Every needs-evidence and needs-adapter scene in the whole parent plan must be included as a visible NOT PRODUCIBLE card. Supported scenes may be omitted from an explicitly short excerpt, but the full coverage table records each omission. The entire output, including its two-second technical lead and all visible gap cards, must fit30 seconds; if all gaps cannot fit, creation is refused rather than silently hiding them.

Source previews are verified as Story previews, not presentation previews. The loader rechecks their complete stored input, derived audience layout, exact Story/source binding, manifest/movie hash, silent policy and captions. A source slice records parent Story task/hash, exact ordered shot and absolute source frame range. It is a derived-story-shot-slice/1.0, not a renamed subset with the original graph hash. Playback stays at30fps. Slices are reencoded and the complete source image is scaled to648×1152, padded at(36,96), preserving all source regions while leaving separate space for a fixed technical banner. Hard cuts/reset semantics are explicit; no state or causal continuity between clips is asserted.

`narrative-preview-status` and `narrative-preview-export` use the excerpt task ID, committed parent/child inputs and CAS. Their exports contain excerpt.mp4, editable excerpt.json, the entire narrative and parent review, a complete coverage/omission table, all child editable Story/animation/source files and a **new pending execution review packet**. The packet binds full child visual/animation/derived renderer input, source slices, real timeline, display policy, environment/codeHash and actual movie SHA. The parent written receipt is retained separately and does not become rendering approval.

The first version deliberately does not render parent titles, on-screen text or authored transitions; those remain editable/exported and are explicitly marked exported-only. Its fixed technical lead/banner/cards replace them in this short profile. Child captions present in the selected frames are retained visually; no narration is spoken and no global caption timing is claimed. Actual fixed text can be inspected in the frozen source and review images. Editing source animation requires a new verified asset/preview; changing the mapping or timing creates a new excerpt task and execution packet. A prior execution receipt becomes stale. This API does not accept a receipt as production or current rendering approval.

Current review, audiovisual quality and final owner/G6 stay pending. Successful full decode/frame counts are technical checks, not semantic truth, a listening result or a perceptual acceptance. No paid API, deployment, target-code execution or formal full-film authorization is implied.
