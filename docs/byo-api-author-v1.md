# Bring-your-own API: explicit author generation

This opt-in path issues **one** OpenAI-compatible Chat Completions request and connects its structured author data to existing source-bound planning. It is separate from Codex/Claude Code session authoring. Ordinary `explanation run` never calls it. Real-provider interoperability, model quality and API-authored speech/video have **not** been verified; all execution tests use synthetic source fixtures and localhost HTTP mock responses.

## Usage

1. Capture a public URL with the existing trusted engine:

```text
node --import tsx src/cli.ts explanation run --repo https://github.com/OWNER/REPO --workspace work/demo
```

2. Copy [the disabled config](../examples/byo-api-v1/config.json) to your owned non-secret configuration file. Set the exact provider `/chat/completions` HTTPS endpoint, model, actual caller-declared pricing and per-call budget. The sample prices are placeholders, not a quote. Put the key only in the named process environment variable using your normal secure environment setup; no key argument, config property, dotenv reader or key persistence is supported. Do not commit credentials.

3. Only after explicit user authorization for that provider, transmission and possible spending, set `enabled: true` and invoke:

```text
node --import tsx src/cli.ts explanation api-author --workspace work/demo --spec YOUR_NON_SECRET_CONFIG.json --out work/demo/api-author-v1 --enable-api
```

Both gates are required. Output must be a fresh `api-author-NAME` child of the owned workspace. Existing output is refused before another API request. A failed/aborted request may still be charged; there are no automatic retries or repair loops. Retain its non-secret failure report and authorize a new destination explicitly if another call is wanted.

The adapter sends pinned source contents/metadata and local author schemas to the chosen provider. Sources are untrusted user-message data, not system instructions. The model gets no tools. Four strict JSON-string fields carry `story.json`, `narrative.json`, `animation.json` and `run.json`; local schemas and the existing planning executor validate them, including source binding/citations. Unsupported or invalid output remains unapproved; syntactic validity is not factual truth.

The new narrative `1.1` profile declares `authorship.kind: api-model` and `api-model-authored-not-semantic-approval`. It does not impersonate a human or Codex session. Legacy narrative `1.0` exports retain their frozen schema bytes. A non-secret `api-report.json` records request count, usage if reported, source/prompt hashes, budget inputs, author-file hashes and pending reviews. Provider request count is not independent proof that a remote model actually executed.

`api-authored-planning-complete` is **planning only**. Inspect it, then use the returned trusted argument array to run `--through speech`, inspect actual recording/caption fit, explicitly adjust author timing if needed, and run `--through preview`. No speech or movie is generated by `api-author`, and it does not automatically fix author errors, fetch deeper sources, interpret feedback or extend timing. Existing session-Agent workflows can perform those tasks; this API adapter is not a general autonomous agent.

## Keyless local continuation

Once an API candidate has completed planning, continue its exact current author locally:

```text
node --import tsx src/cli.ts explanation api-continue --workspace work/demo --out work/demo/api-author-v1 --through speech
node --import tsx src/cli.ts explanation api-continue --workspace work/demo --out work/demo/api-author-v1 --through preview
```

These commands accept no API config, key or enable flag and issue zero provider requests. They verify the original planning receipt, all four author-file hashes, current captured source/author identity and the existing executor's lock-time checkpoint precondition. Stale candidates are refused rather than silently switched into the project. Each continuation appends a separate report; the original API receipt stays unchanged. Identical preview repeats reuse verified local caches.

A failed/timing/caption checkpoint is not a completed movie. The command does not repair author data or extend timing. A current session Agent can create an explicit versioned correction with the existing revision workflow; do not rerun the API merely to retry a local tool or bypass the original-candidate hash guard. Claude's thin project skill now describes this same local recovery path, without tool pre-approval or inferred spending authorization.

The opt-in smoke below uses synthetic captured sources and a literal localhost mock response, then **closes its server before local continuation**. It produces real local narration, an editable preview and a cached repeat; it does not exercise a real LLM or Claude Code:

```text
node --import tsx --test tests/byo-api-preview.node.ts
```

It requires the already installed trusted media runtime (including local Windows speech support), and never installs a browser, account or target repository. See [reference comparison and actual evidence](open-reference-local-preview-v1.md).

## Transport and spending boundaries

Only the Chat Completions JSON-envelope subset with `response_format.json_schema`, `strict: true`, `max_tokens` and a complete `finish_reason: stop` text response is supported. Providers lacking those features fail closed; there is no silent downgrade. See [OpenAI structured output documentation](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat). Domain schemas stay in the prompt; the provider's strict response schema is a simple four-string envelope.

Remote endpoints require HTTPS and public IPv4. Every resolved IPv4 address is screened; the chosen address is pinned during connection, preserving normal TLS hostname verification. Credentials/query/fragment URLs, private/reserved addresses, public IPv6-only endpoints and redirects are refused. Plain HTTP requires `allowLocalHttp: true` and a literal `127.0.0.1` or `[::1]` endpoint; this is intended for explicitly selected local models/tests, never arbitrary LAN or metadata hosts. No header/config changes can be supplied by model output.

Each call has an output-token request bound, I/O timeout, 2 MB request limit and 4 MB response limit. Before sending, the local estimate uses encoded request bytes as a conservative input-token estimate plus maximum output tokens, at caller-declared rates in USD micros per million tokens. `maxEstimatedCostMicros` is a **local authorization estimate, not a provider-enforced billing cap**. Verify pricing and provider-side limits yourself; remote accounting, tokenizer overhead and charges on failure cannot be guaranteed locally. Zero prices mean the caller explicitly declares zero cost; the engine does not establish that a service is free.

The key is sent only as the configured endpoint's Authorization header, never as model prompt content. Literal/JSON-decoded credential echoes are rejected before persistence. No raw provider response/error body or underlying transport exception is stored or printed; failure reports retain sanitized codes. Existing operating-system permission controls still apply, and this feature grants no sandbox bypass or spending authorization from repository text.

## Verified scope

Eight focused tests use actual localhost HTTP sockets, including an actual CLI subprocess reaching immutable source-bound planning. They cover explicit gates, env-only keys, output reservation, private/redirect refusal, budget denial, timeout, size bounds, malformed/truncated/tool/extra-file output, credential echoes, stale source binding and API authorship. Directly affected legacy narrative/run regressions also pass, including frozen schema identity. No target repository execution, real provider/key, paid API, Judge, formal film or API-authored media run occurred. [Recorded evidence](evidence/byo-api-2026-11-05.json) distinguishes these checks from unperformed provider/semantic/media verification.
