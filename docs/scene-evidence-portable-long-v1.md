# Scene evidence overrides for complete portable runs

A read-only audit found a real integration gap: mixed animation profiles shared one global Story evidence graph, so a faithful new double-input compose could not coexist with rembg's existing single-input chain. The animation compiler correctly refused that mismatch. No new renderer/profile was needed.

The run-only `story.json` envelope is now explicitly `narrative-scene-evidence/1.0`, containing `baseStory` (the unchanged standalone Story contract) and ordered `overrides: [{sceneId, evidence}]`. Only already-supported scenes may be overridden. Each override must retain exact same-source metadata and a subset of canonical base claims, including their literal raw values before schema normalization. It must close every claim used by the original scene's exact shots. Unknown/repeated/reordered/gap scenes, changed/foreign sources, altered claim statements (including trimming tricks), missing claims and unknown executable fields are refused. Timing, narration, visual text and shot identity still come from the base Story. Actual URL-capture source hashes/exact quotations are subsequently verified by the existing Story binding stage; reference equality alone does not establish semantic entailment.

Unified planning, per-scene asset preparation and controlled portable author verification share the same resolver/derived-Story function. The authoring packet exposes the new run-only schema; old standalone Story inputs and animation profiles stay supported. Derived child IDs preserve the prior scheme. Every actual child Story/graph hash and authored animation is checked in the current execution closure; no historical review becomes approval of the replacement evidence/visual connection. The user requests edits in prose; the current session Agent authors the four data files. There is no hidden model dispatcher or target execution.

A first real run caught a missed argument in the second (animation-stage) resolver call. Planning used the override, but animation preparation accidentally used the base graph and correctly stopped before rendering. The single-line call was fixed and an actual heterogeneous-graph positive was added (the same animation fails without its evidence map and succeeds with it). That failed candidate remains in the immutable run attempt history; no old media was overwritten.
