# Natural-language feedback through an explicit session-Agent plan

The user gives prose feedback. The current conversation Agent interprets it, identifies the supported scene, checks its fixed sources and writes an explicit narration/visual/timing plan. The executor never receives prose as an instruction to infer edits, dispatches no model and grants no semantic or owner approval. The user does not author JSON.

```text
node --import tsx src/cli.ts explanation feedback-context --workspace WORKSPACE --out WORKSPACE/feedback-context.json
node --import tsx src/cli.ts explanation feedback-apply --workspace WORKSPACE --spec WORKSPACE/agent-feedback-plan.json --out WORKSPACE/feedback-one --through speech
node --import tsx src/cli.ts explanation feedback-apply --workspace WORKSPACE --spec WORKSPACE/agent-feedback-plan.json --out WORKSPACE/feedback-one --through preview
```

The context is read only and exports the verified current result/author/source identity, exact scene and normalized animation hashes, and the plan schema. Source and scene prose remains untrusted data. The Agent explicitly supplies the original feedback, its interpretation, per-scene reasons and the actual new text, existing bounded animation data and any authored timing. `origin` is caller-declared metadata (`user` or `session-agent-validation`), not authenticated user consent or a review receipt. The interpretation itself remains pending semantic review.

`feedback-apply` creates a new child author fork and preserves exact plan bytes, a source/current-author context and a before/after report. Narration uses the existing guarded full-recording caption rewrite; animation uses the existing source-bound compilers. No source assertions, citation claims, graph evidence, scene order, gap dispositions or unsupported capabilities are added. Visual patches require an actual animation or context change: description/title-only export edits cannot masquerade as changed rendered visuals. Optional explicit timing is an Agent decision, never automatic measured padding, audio trimming or stretching. All scenes remain subject to complete-story budget and actual speech/caption checks.

The speech stage must be ready before media acceptance. If a recording or caption does not fit, the Agent makes a new explicit plan from the current checkpoint, retaining the first candidate. The prepared author must not be silently mutated: its hash and plan bytes are guarded. Repeating the exact plan/out resumes its own checkpoint; an already completed requested stage returns without executing again. Another workspace revision, changed plan bytes, wrong source, stale scene/animation/text hash or a modified prepared author is refused. The existing workspace lock/current-author precondition also fences execution after preparation.

Current scope is complete2.0, produced single-shot scenes, the existing animation profiles and single whole-recording caption rebuilds. Gaps, multi-shot scene selection, ambiguous scene ownership, source-fact changes, automatic subtitle resegmentation, arbitrary target runtime simulation and new adapters require separate Agent authoring. No visual-only background model or natural-language parser exists. A crash during candidate preparation may leave a retained incomplete child requiring a fresh output path; forced process-kill recovery of that small preparation window was not tested.

## Two real-project validations

Independent workspaces under `work/mri` and `work/date` were restored from read-only SQLite backups and regular CAS copies of the real captured MRI CLI-parser and date-fns calendar projects. Original workspaces were not written. Baseline51-second movies were rendered under this code version. The session Agent then authored two actual validation feedback plans, with origin explicitly `session-agent-validation` rather than an invented user review. Exact examples are in `examples/feedback-plan-v1`; their checkpoint hashes are historical evidence, not templates to copy onto a different current result.

MRI feedback: “例子太抽象，请把 --foo bar 的输入和结果说清楚，画面先强调输入，再出现结果。” The Agent mapped this to the example chapter, new concrete input/output labels, a rewritten sourced script and delayed output animation. The MRI doc/source unknown-option discrepancy remains unresolved in the limitation chapter.

Calendar feedback: “请读清2012年9月1日这个日期，先显示日期，稍后再亮文档结果为真，并保留未运行说明。” The Agent mapped this to its sourced document example, explicitly retained the unexecuted-example disclosure and changed the date/result display. Neither case changed declared factual assertions or cited source bytes. Both explicitly chose an11-second example shot before speech measurement, making feedback movies52seconds/1560frames; this was an authored decision, not automatic audio fitting.

Both actual plans passed speech/caption preflight and rendered through `feedback-apply`. Only the example source scene and recording regenerated in each project; the other four source/recording caches and mixed-PCM recording segments remained identical. All four movies passed full FFmpeg decode, physical H264/AAC frame/duration checks, complete five-scene/whole-recording closure, exact burned-caption text and silent lead/gap/tail checks. Original author hashes, request/source bytes and baseline MP4 hashes remained unchanged. Every exported source copy matched its captured digest. Exact-input repeats with network disabled hit all scene, speech and movie caches, and completed feedback-plan retries executed zero actions. Actual stale-plan and changed-request retries were refused without replacing candidates. Edited input/output frames were viewed.

Sixteen targeted cases passed across explicit feedback mapping/refusals and the reused prose/scene-animation validators; TypeScript passed. The first test run exposed a fixture character-count expectation and TypeScript narrowing mistakes; these were corrected without a production behavior change. No Judge, paid API, target installation/execution, deployment or formal full film occurred.

Local comparison pages are `work/mri/comparison.html` and `work/date/comparison.html`. Exact plan bytes, contexts, before/after reports, run results, negative guard records and frame samples remain there. `work/feedback-verification.json` and each `checks/verification.json` record actual results; `scripts/verify-narrative-feedback-experiments.mjs` performs the physical/closure/history/cache assertions. Semantics, pronunciation, word alignment, natural listening, continuous AV, audience quality and final owner acceptance remain pending.
