# Relocating a complete experimental preview

For a supported data-package command instead of manual directory copying, use [portable complete project export/import](portable-long-project-v1.md). The manual experiment below is preserved as historical evidence.

A complete-profile project is portable data for a compatible trusted engine checkout. It is not a standalone editor. Start with a new empty destination; use a short absolute Windows path because SQLite and publication paths remain bounded. Close all writers first; a nonempty SQLite WAL requires a consistent database backup/checkpoint rather than copying only the main database. Preserve the original project until verification completes.

Copy these regular files/directories, refusing symlinks and special files:

- `workspace.json`, `request.json`, `source.json`;
- the selected complete author directory, renamed to `author` if useful;
- `state/tasks.sqlite`, `state/tts.sqlite`, and all `state/artifacts`.

Do not copy `runs`, old publication directories, temporary files, locks or the active-run marker. Export publications contain ownership tied to their original absolute path; the executor creates fresh publications from verified local CAS at the new path. The copied state includes historical artifacts, not just a minimal reachability-pruned archive.

Run the trusted engine with `explanation run --repo <EXACT_OWNED_GITHUB_URL> --workspace <NEW_DIRECTORY> --author <NEW_DIRECTORY>/author --through preview`. A captured source is reused without fetching. A missing or altered source/request/author binding is refused. Complete author schema2.0 and the experimental complete profile retain every scene and every full original-speed recording, with no automatic padding or clipping and a300-second budget including lead/gaps.

Edit `author/animation.json` to change an established scene's choreography, then rerun the same command. This regenerates the affected source scene and final assembly while retaining unchanged source scenes and recordings. Edit the owning Story/narrative/run inputs together for timing, narration, scene ordering or evidence changes; exact scripts require new complete recordings and authored caption partitions. Unsupported operations cannot be introduced by arbitrary fields. Local Windows Huihui is needed for uncached new Chinese speech. Source interpretation, independent semantic review and final listening/owner acceptance remain explicit work.

Source movies include the engine/environment fingerprint. Moving within a compatible unchanged environment can reuse them; changing renderer code, runtime, browser or other bound environment inputs can invalidate them. A code upgrade that regenerates movies is not proof of a failed data relocation. Verify a same-version second run and then a bounded edit separately.

The migration experiment uses `work/long-portable.ts`, which copies closed regular state into clean destinations, temporarily renames each original workspace away, disables `fetch`, runs a complete preview, repeats it for cache verification, edits one animation, and fully decodes both movies. Originals are restored in `finally`. It checks nine-scene coverage, eight full recordings/caption closures, full timeline samples, silent evidence gaps, scene cache isolation and unchanged mixed PCM. Evidence lives in `work/long-portable-checks/{rea,rembg}`; task IDs and actual outcome are in their result/verification JSON files. This is a same-machine/new-absolute-path experiment, not proof of cross-OS, missing-dependency or authenticated-review portability. It does not generate an approved formal film or establish90% product readiness.

## Actual results on baseline6e5aff5

Both projects passed the complete experiment. REA retains95seconds/2850frames and87.01seconds of complete speech. rembg retains98seconds/2940frames and89.22seconds of complete speech. Each has nine narrative scenes, eight complete recordings, full captions and an explicit silent evidence gap. All four original/edited migrated movies fully decode. REA's threshold action and rembg's compose action were each changed from their original animation timing to end0.58; only the affected scene movie and assembly regenerated, with the other seven scenes, every recording and parent plan cached. Mixed PCM remained identical. Each export contains all raw pinned sources with matching hashes (REA5, rembg3), full narrative/source metadata and eight editable child Story/animation/compiled/provenance/manifest closures.

The baseline differs from the older source-media engine version, so first migration reused Stories/assets/voices/plan but regenerated version-bound source movies. To directly test video-cache relocation too, `work/long-portable-same-version.ts` copied the now-closed state again into a third empty path without runs/publications, hid both preceding workspace roots, disabled fetch, and reran. **Both second relocations reused every scene/movie/voice/plan/final task and reexported byte-identical MP4s.** No additional movie render was needed. All originals were restored.

Current self-contained project-data roots are `work/long-portable-v3-rea` and `work/long-portable-v3-rembg`. Their `README.txt` and `portable-project.json` give the relative display path, exact repository and reusable run command. The edited long tasks are REA `4c205ea439c561231bc62a4721cfb864ab94fd7a2487e9f14ea3df57d1bb54cd` and rembg `318bfd45505ebb725a78b84a367bf41e6648febf3025d5085770825ae383df69`. Verification includes `verification.json`, `editable-closure-verification.json` and `same-version-relocation.json` under each evidence directory. No runtime fix or additional unit regression was necessary; the checks exercised actual source/state restoration, media generation, editing, caching and exports. Semantic interpretation, speech accuracy/listening, continuous perceptual AV and final owner acceptance remain unverified, and diagnostic diagrams/export-only parent text remain presentation limitations.
