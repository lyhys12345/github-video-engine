# Fact review sidecar

`github-video explanation fact-review --task <accepted-proposal-checkpoint> --data <state> --out <new-directory> [--spec <receipt.json>]` exports a source-bound review packet and receipt schema; with a receipt it also verifies the attributed judgments. The command checks the committed proposal, citations and exact source bytes again. Every required item must have a verdict, rationale and limitations. Read `result.status`: an unresolved receipt can still exit with code 0 because the command successfully processed it.

This is an evidence and review handoff, not automated semantic verification. Reviewer identity is not authenticated; receipts do not grant approval and do not update the session's pending semantic review. Do not mistake accurate quotations for proof that a claim is true. A new proposal or packet requires a new receipt. The Story adapter is an API only, not a public Story workflow; downstream captions, actual frames and presentation parameters still require separate review.

The real narrated fd revision was rendered and decoded with Windows Huihui, not the previously preferred Chen voice. Its audio was not listened to, and naturalness and word-level alignment remain pending owner review. See the independent reports in `reviews/fact-review-v1` and `reviews/voice-revision-v1` for the candidate-specific evidence and limitations.

## Durable presentation review binding

The sidecar can now include the complete authored presentation. Write a JSON wrapper `{ "mode": "silent", "plan": <presentation-plan> }` or `{ "mode": "narrated", "spec": <narrated-render-spec> }`, then pass it with `explanation fact-review --task <proposal-checkpoint> --presentation <wrapper.json> --data <state> --out <new-directory>`. The narrated spec includes the exact voice-preparation manifest hash, offsets and authored caption cues. Every proposal item and the entire canonical presentation require a receipt judgment. This reviews authored data; it does not observe actual pixels, spoken audio, caption accuracy or listening quality.

Pass the resulting complete receipt to `explanation render`, `explanation narrated-render` or `explanation revise` using `--review <receipt.json>`. The parsed canonical receipt becomes part of the new durable render input and task identity. `status`, `resume` and `export` reverify the exact source bytes, proposal and presentation without rereading the original receipt path. Exports include `fact-review/packet.json`, `fact-review/receipt.json` and `fact-review/result.json`. Status exposes `factReview` as attributed reviewer judgments, with `semanticTruth: not-machine-verified`, `identityAuthentication: not-provided` and `approval: none`. Existing `review.semantic`, audiovisual and owner-acceptance fields remain pending.

A missing, duplicate, stale, unsupported or unverified receipt item prevents a render requested with `--review` from starting its child renderer. `fact-review --spec` still reports unresolved receipts without granting approval. Explicit previews without `--review` remain available and pending. Revisions never inherit their base receipt: a changed manuscript, parameter, timing, voice binding or caption requires a new presentation packet and receipt. A revision without a new receipt is unreviewed, even if its base was reviewed. Historical tasks without review inputs retain their previous identity and exported manifests.

The receipt is an optional attributed handoff, not an authenticated approval gate. Anyone with local state access can author an attribution; supported verdicts do not prove truth. This feature does not certify real render appearance, speech realization, exact word alignment, owner acceptance, deployment or production permission.
