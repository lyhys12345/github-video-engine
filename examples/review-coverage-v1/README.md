# Review checklist coverage integrity

The old receipt verifier checked hash consistency and completeness against `requiredItems`, without proving that this list still covered every claim and authored unit in the packet. On two real historical packets (clsx and rembg), deleting one checklist entry and recomputing its packet hash passed that old hash/list predicate. This could mislabel incomplete coverage as `attributed-review-complete` if an inconsistent packet reached the verifier.

The verifier now independently reconstructs the exact ordered checklist from all packet claims and units. It rejects omitted/extra/reordered entries, duplicate claim IDs, colliding claim/unit identities and unknown unit claim links. The pending worksheet exporter shares the same invariant. Existing valid packet/receipt hashes and historical author/source data remain unchanged; this does not authenticate reviewers or establish semantic truth. An attacker replacing both content and hashes still requires external exact candidate/provenance binding; hashes are not signatures. Current task materials already regenerate trusted packets against source inputs, and this patch strengthens the reusable verification boundary.

`result.json` records read-only checks against actual exported clsx and rembg packets. Its synthetic test receipts are clearly TEST ONLY and exist only in memory to exercise mechanical validation. No actual review was started, imported or marked accepted. Original raw packet bytes are checked unchanged. Source fact review stays pending, approval none. No media, paid API, target repository code or Judge runs.

Run `node --import tsx examples/review-coverage-v1/verify.ts <clsx-packet.json> <rembg-packet.json>` from the checkout. Results go to `work/review-coverage-v1/result.json`. Existing paths are recorded in committed result.json. Targeted `tests/fact-review.test.ts`:22 tests pass; TypeScript typecheck passes. Additional source/script edits, evidence and complete execution changes still invalidate old receipts via exact packet/candidate hashes; no historic receipt is upgraded or rewritten.
