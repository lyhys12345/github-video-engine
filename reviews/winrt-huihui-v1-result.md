# Windows Huihui local voice: technical verification

Frozen candidate `d373039aedeff5bfa604a31a84cea2f0ecbe6d3a2ea1fc81cc6a341c9325a49a` adds a separate, bounded Windows WinRT Huihui zh-CN short-text generation task and versioned import linking exact submitted text, original WAV and generation manifest. Existing imported voices and remote provider handling remain separate. Successful cached generation reuses committed bytes rather than assuming resynthesis is byte-deterministic.

Real generation produced a 7.175-second mono 16 kHz WAV and a source-bound 9-second, 216-frame H.264/AAC Chinese technical preview; both fully decoded. Independent reviews checked source/receipt binding, cache, actual worker cancellation and resume, malicious input as data, tampering, historical reads and PCM/AAC. The technical fixture is Huihui, not Chen; transcript accuracy, naturalness, continuous listening and owner acceptance were not checked. The adapter makes no explicit remote API call, but Windows speech subsystem network activity was not audited. Two prior same-text tests produced different hashes, so reproducibility must not be assumed. Independent imports produced different downstream IDs due to receipt timestamps even when WAV bytes matched.

Product review identified a medium Chinese caption issue in actual frames: the word “问候” split over two lines with a lone final character. The provider technical slice passed, but Chinese visual quality is not approved. Other retained minor issues: CLI validation errors use a generic `UNEXPECTED` category, and one historic proposal incorrectly labels a Chinese fixture English.
