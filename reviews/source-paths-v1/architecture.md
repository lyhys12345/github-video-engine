## Architecture decision

Request 1.2 requires a full commit and ordered one-to-three explicit source paths. Start identity includes packet 1.3 and capture profile `github-pinned-git-blob/1.0`. Unsupported profile/request combinations are rejected. Old request/start branches do not receive new defaults or fields. Source order remains identity-relevant rather than silently being canonicalized into a set.

The existing read-only primitive walks Git commit/tree entries, requires ordinary file modes, rejects incomplete trees, verifies blob SHA-1 from exact bytes and tree entry identity, validates canonical base64 and UTF-8, and preserves BOM/CRLF. The session captures all requested paths before committing its successful snapshot. Re-read verifies stored artifact closure, pinned URL/hash, ordered path tail, budget and author-packet identity. Export uses numeric filenames; repository path strings are not interpreted as local destination paths.

The added source files are inert untrusted evidence. The work package explicitly instructs the author to ignore repository instructions, read code as text, author claims and disclose illustrative/inferred content. Exact quotation and binding checks are not semantic proof. Ordinary README/documents use their retained legacy capture procedure; this review does not claim every source is newly verified as a Git blob.

**Future compatibility condition, not a current defect:** the global authoring capability constant, generated proposal schema and unsupported mechanism check remain shared. This candidate is safe within its stated evidence-only scope because those mechanisms are unchanged. Adding a hidden-file adapter later still requires version-dispatched capability/schema/validation behavior; packet 1.3 and capture profile alone do not solve that future migration.
