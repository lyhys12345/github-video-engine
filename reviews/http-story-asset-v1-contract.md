# HTTP Story to editable assets acceptance contract

This isolated checkpoint uses a live, pinned Express documentation capture and an authored scenario to test the transition from URL research to editable animation. The deliverable is an experimental SVG asset pack with estimated timing and pending review. The historical URL intake candidate and audiovisual evidence remain separate.

| ID | Required behavior | Roles |
| --- | --- | --- |
| H1 | Story accepts a typed HTTP request, matching handler, and response chain, with claim and actor checks. The fixed legacy explain graph retains its supported operations and existing REA/rembg inputs. | product, reliability, content_facts |
| H2 | A successful repository-bound Story task feeds asset planning with its exact graph and pinned bytes. Asset status and export preserve and verify Story task, graph, and repository lineage. Unbound tasks reject and the original manual asset path remains available. | reliability, evidence, security |
| H3 | Fresh Express intake resolves a full commit. The authored root-route Story uses exact evidence lines and exports editable assets and nine diagnostic samples. Human review status, complete disclosure that the request and response are illustrations, and estimated timing are visible. Transfer arrows show the request and route direction and the response returning to the client. Mid-transfer endpoint labels remain separated in the diagnostic samples. | product, evidence, content_facts |
| H4 | Public commands, cancellation and existing safety boundaries remain intact. No paid calls, repository execution, observed HTTP result, new audio or movie are claimed. Source, evidence and tests are frozen and active judges review the same bytes. | product, reliability, evidence, security |

The three rasterized samples are diagnostics. Continuous audiovisual review and final human acceptance remain separate.
