## A-R1 — resumed revision may rebind its child under the same revision ID (major)

The revision task key hashes base task ID and edit only (src/workflow/explanation-contract.ts:149). The outer task invokes renderExplanationPlan or renderNarratedExplanationPlan anew on each attempt (explanation-session.ts:771–782). Both helpers recalculate plan and current renderer environment, and narrated mode also recalculates voice placement identity (lines 618–629, 647–668). Resume reads the outer input and re-enters that path (lines 791–795). The ordinary render paths instead retain their typed input, including child plan identity and renderer environment, and check environment before running (lines 499–548). A completed revision receipt itself remains immutable. The gap is at recovery before its own receipt, where identical logical revision identity does not select one immutable child execution.

Expected: resume should use the originally identified child execution; if a changed environment prevents it, report the mismatch and require a fresh explicit revision identity. If the original child already committed, recover that verified result. Fix by persisting typed RenderInput/NarratedRenderInput including compiler, voice-placement and renderer binding before announcing the revision task, or by a separately verified, immutable preparation/checkpoint receipt selecting exactly one child. Recheck both unchanged-environment resume and drift, including cancellation after child completion before outer receipt.

## A-R2 — parent deadline may cut off otherwise supported durations

explanation-session.ts:527 and :548 bound normal render to 3,120,000 ms. The wrapper at :782 gives its entire nested execution 480,000 ms, including task setup and verification. TaskRunner forwards outer cancellation to nested work and sets a retryable TIMEOUT at tasks.ts:103. Documentation has no separate duration policy for revisions. The independently recorded 568.984 s, 300.000 s test in reviews/presentation-300s-pressure-v1-result.md is a technical sequence fixture rather than this candidate's equivalent revision path. It establishes that the project's supported long media can take longer than 480 s, without demonstrating a revision timeout on this host. Align the outer deadline with nested execution plus overhead or document/enforce a distinct revision limit before rendering. A real or carefully controlled slow-child exercise can verify the boundary without waiting for repeated failures.
