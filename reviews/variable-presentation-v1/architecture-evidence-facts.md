## Architecture conclusion

The implementation has a real, separately versioned presentation path (`repository-presentation-plan-v1`, `repository-presentation-preview-v1`). `PresentationPlan` is strict, 1–20 beats, each at least 24 frames, 24 fps, total at most 1440 frames. Every saved proposal beat must appear once in its original order. The two module state machines validate typed event order, event frame bounds, role IDs, documented parameter citation indexes, and event-to-beat/mechanism claim links. State persists across beat boundaries, including event-free context/limitation holds. No README parsing or repository-name dispatch determines animation events. Actual authored data selects the module and events.

Compilation and rendering remain bounded illustration capabilities: HTTP listen/request/match/respond, or one canonical subject with image-input/cutout/mask selection/comparison. They do not express arbitrary queueing, branching workflows, actual rembg internals, scalar simulation, or all repositories. The `adapterCandidate` is an author assertion, not an automated semantic classifier. Actual p-limit proposal was independently rejected by pure compilation and `createPresentation` before a task database was created; the copied proposal workflow remained intact.

Full original/revised proposal-to-plan-to-persisted-trace-to-preview closure was independently loaded for four cases. Every exported file equalled the corresponding checked CAS bytes. For all **2,136 frames**, independently accumulated event state and beat offsets agreed with the frame function; all traces recompiled byte-identically. Timings are presentation frame counts, not measured network latency, inference speed, or target execution time. A 24-frame easing interval is animation, not a claim about project duration.

Input/reference negative checks rejected wrong proposal hash, wrong commit, cross-project module, absent citation index, illegal transition, wrong event claims, missing beat, over-60-second duration, and out-of-beat event. Direct corruption of plan/trace/source/movie CAS was rejected, and restoring original bytes restored verification. These are integrity checks, not authentication against unrestricted same-account replacement of an entire internally consistent data store.
